Column widths, order, and pinned selection are stored per user. The package offers two storage mechanisms.

## Session storage (default)

- Enabled by default — no setup required.
- Stores settings in the user's session.
- No database needed.
- Storage is **browser/device specific** — settings don't follow the user across devices.

## Database storage (optional)

- Stores settings in the `table_settings` table.
- Requires the [published migration](/getting-started/installation#publish-and-run-migrations-optional).
- Works **across browsers and devices** for the same user.

Enable it on the panel plugin:

```php
ResizedColumnPlugin::make()
    ->preserveOnDB(true); // enable database storage
```

## Configuration priority

When the package decides whether to save to the database, it checks configuration in this order. **The first match wins.**

| Priority | Method | Scope |
| --- | --- | --- |
| **1 — Highest** | `->preserveColumnWidthsInDatabase()` table macro | Single table only |
| **2** | `ResizedColumnPlugin::standalone()` in `AppServiceProvider` | All components, no panel required |
| **3 — Lowest** | `ResizedColumnPlugin::make()` in the panel provider | Inside a Filament panel |

A table macro always wins over the global standalone config, which always wins over the panel plugin config. See [Standalone usage](/essentials/standalone-usage) for the macro and standalone forms.

## One row per user

Whichever backend you choose, widths, column order, and pinned columns share **one persisted record per user** — there's no separate storage or migration per feature.
